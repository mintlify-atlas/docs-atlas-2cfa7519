## Overview

EduStream uses Vue Router 4.5 for client-side routing. The application features a multi-layout structure with nested routes for dashboard functionality and standalone pages for authentication and live streaming.

## Router Configuration

The router is configured in `src/router/index.ts` using HTML5 history mode:

```typescript src/router/index.ts
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes,
})

export default router
```

<Info>
  The router uses `createWebHistory` for clean URLs without hash fragments. This requires server-side configuration to redirect all requests to `index.html`.
</Info>

## Programmatic Navigation

### Using Router in Components

```typescript Navigating to Routes
import { useRouter } from 'vue-router'

const router = useRouter()

// Navigate to a named route
router.push({ name: 'chats' })

// Navigate with parameters
router.push({
  name: 'call',
  params: { id: userId }
})

// Navigate to live stream
router.push({
  name: 'live-viewer',
  params: {
    link: streamLink,
    id: streamId
  }
})
```

### Router Methods

<CodeGroup>
```typescript Push
// Add entry to history stack
router.push('/dashboard/chats')
router.push({ name: 'users' })
```

```typescript Replace
// Replace current history entry
router.replace({ name: 'login' })
```

```typescript Go
// Navigate through history
router.go(-1)  // Go back
router.go(1)   // Go forward
```
</CodeGroup>

## Layout Strategy

### Main Layout

The `MainLayout` component wraps all dashboard routes:

```vue Layout Structure
<template>
  <div class="dashboard-layout">
    <Sidebar />
    <main>
      <router-view />  <!-- Child routes render here -->
    </main>
  </div>
</template>
```

### Standalone Pages

Routes like `/login`, `/liveHost/:id`, and `/liveViewer/:link/:id` render without the dashboard layout:

```typescript Standalone Routes
// No parent layout - full control over UI
{
  path: '/login',
  name: 'login',
  component: Login,
}
```

## Route Organization

### By Feature

- **Authentication**: `/`, `/login`
- **Dashboard**: `/dashboard/*`
- **Communication**: `/dashboard/chats`, `/dashboard/call/:id`
- **Live Streaming**: `/liveHost/:id`, `/liveViewer/:link/:id`
- **Settings**: `/dashboard/settings/*`
- **Testing**: `/host`, `/viewer`

<Note>
  The route structure mirrors the application's feature organization, making it intuitive to navigate the codebase.
</Note>

## Best Practices

### Named Routes

Always use named routes for navigation:

```typescript
// Good
router.push({ name: 'call', params: { id: '123' } })

// Avoid
router.push(`/dashboard/call/123`)
```

### Route Guards

<Info>
  While not currently implemented in the codebase, authentication guards should be added to protect dashboard routes.
</Info>

```typescript Example Auth Guard
router.beforeEach((to, from, next) => {
  const isAuthenticated = checkAuth()
  
  if (to.path.startsWith('/dashboard') && !isAuthenticated) {
    next({ name: 'login' })
  } else {
    next()
  }
})
```

## Common Patterns

### Call Flow Navigation

```typescript Call Navigation Pattern
// Step 1: Initiate call (calling screen)
router.push({ name: 'calling', params: { id: targetId } })

// Step 2: Call accepted (active call)
router.push({ name: 'call', params: { id: targetId } })

// Step 3: Minimize call (continue using app)
router.push({ name: 'mini-call' })
```

### Live Stream Workflow

```typescript Stream Navigation
// Host starts stream
router.push({ name: 'live', params: { id: streamId } })

// Viewer joins stream
router.push({
  name: 'live-viewer',
  params: { link: shareLink, id: streamId }
})
```
